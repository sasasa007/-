# 핵심 화면 검증 (PRD §5.2 와이어프레임 대조)

> 생성: 2026-05-21 · 대상: index.html (SPA, 단일 파일 내 7개 뷰)

## 아키텍처 노트
PRD는 화면별 라우트(`/day/:n`, `/card/...`)를 명시. 현재는 **단일 index.html + Alpine 상태(`view`) + 해시 라우팅**으로 구현. 화면 전환은 `x-show="view === '...'"`로 처리. 브라우저 미리보기에서 전 화면 렌더링·전환 동작 확인 완료.

| 뷰 | index.html 위치 | 라우트 |
|---|---|---|
| home | L49 | `#/` |
| day | L90 | `#/day/:n` |
| zone | L161 | `#/zone/:z/:day` |
| card | L214 | `#/card/:id/:day` |
| checklist | L256 | `#/checklist` |
| tools | L286 | `#/tools` |
| emergency | L317 | `#/emergency` |

## 미구현/차이 요약 (와이어프레임 대비)
- ❌ Multi Zone(Big Bus) 타일 — Day 화면
- ❌ 카드 상세의 "호텔→소요시간(걷기/튜브/우버)" 표시 + 데이터
- ⚠️ 지도: PRD는 임베드 iframe, 현재는 외부 앱 URL 연동
- ⚠️ Butler / 오늘의 추천 / 실시간 발견 — Phase 2 (의도된 미구현, 안내 처리)
- ⚠️ 동선 최적화·골든벨·진행률·추억 화면 — Phase 3/4 (Phase 1 비대상)

## 판정
Phase 1 핵심 화면(홈·Day·Zone·카드·체크리스트·응급·도구) **모두 구현·동작 확인**. AI/실시간 의존 요소는 정직하게 "Phase 2/3" 안내로 자리 확보. 와이어프레임 대비 사소한 누락(Multi Zone, 호텔 소요시간) 존재.
